第3回 データの前処理

生データをそのまま使うとどうなるか？

場面：「身長と年収、どっちが効く？」

左では身長の差が点にしか見えません。距離はほぼ年収だけで決まります。

今回の問い

ワインの化学組成（アルコール度数、色の濃さ、プロリン量…）から産地3種を分類したい。

  • 変数は13個。だが単位もスケールもバラバラ（プロリンは数百、色相は1前後）
  • 外れ値もカテゴリ変数も混じっている

生データをそのまま手法に渡すとどうなるか？ 今回のキーワードは「前処理」。

扱うデータ：Wine データセット

標本数 = 178 本,  説明変数 = 13 個,  クラス = 産地3種
                     min     max   mean    std
alcohol            11.03   14.83  13.00   0.81
malic_acid          0.74    5.80   2.34   1.12
ash                 1.36    3.23   2.37   0.27
alcalinity_of_ash  10.60   30.00  19.49   3.34
magnesium          70.00  162.00  99.74  14.28
total_phenols       0.98    3.88   2.30   0.63
  …（全13変数）

各行が1本のワイン、列が化学測定値。プロリンは平均747、色相は平均0.96 ——桁が3つも違う。

データの四角形：列ごとに揃える

前処理は列ごとの操作。各列が自分の平均・散らばり・単位を持つ——これを揃えるのが今回の主題。

散らばりを見る：スケールの違い

外れ値も混じっている

リンゴ酸も色の濃さも右に長い裾。少数の大きな値が、平均や分散を引っ張る。

素朴な方法：生データのまま KNN で分類

knn_raw = KNeighborsClassifier(n_neighbors=5).fit(X_train, y_train)
acc_raw = accuracy_score(y_test, knn_raw.predict(X_test))
print(f"生データ KNN の正解率 = {acc_raw:.3f}")
生データ KNN の正解率 = 0.722

標準偏差が変数間で1000倍以上違うのが原因です。

なぜ失敗するか：距離が一変数に支配される

d(\mathbf{a},\mathbf{b}) = \sqrt{\sum_{j=1}^{p} (a_j - b_j)^2}

スケールの大きい変数がモデルを支配する。

位置づけ：前処理は解析フローの「土台」

前処理を誤ると、後段のモデルがどれだけ優秀でも結果は崩れる。

行列で見る：標準化は列の一括変換

\mathbf{X}_{std} = (\mathbf{X}-\mathbf{1}\boldsymbol{\mu}^\top)\,\mathbf{D}_\sigma^{-1}

標準化＝列の操作。

定義①：標準化（z-score）

z_j = \frac{x_j - \bar{x}_j}{s_j}

  • 変換後はどの変数も「平均から標準偏差いくつ分か」で測れる
  • 外れ値には引かれるが MinMax よりは頑健

最も汎用的なスケーリング。 迷ったらこれ。

定義②：MinMax 正規化

各変数を区間 [0,1] に押し込む。

x'_j = \frac{x_j - x_{\min,j}}{x_{\max,j} - x_{\min,j}}

読み方：最小値を引いて、幅（最大−最小）で割る。0から1に収まる。

範囲が決まるので画像やニューラルネットで好まれる。 ただし最大・最小は外れ値そのもの。1点で全体が決まる。

定義③：ロバストスケーリング

平均・標準偏差の代わりに中央値と四分位範囲を使う。

x''_j = \frac{x_j - \mathrm{median}_j}{\mathrm{IQR}_j}, \quad \mathrm{IQR}_j = Q_{3,j} - Q_{1,j}

読み方：中央値を引いて、四分位範囲で割る。外れ値に引きずられにくい。

  • どちらも順位ベースなので外れ値の影響を受けにくい

3手法は「何を基準にスケールを測るか」が違うだけ。

3手法を1変数で比較

分布の形は変わらず、目盛だけが揃う。 どれを選んでも順位や相関は保たれる。

外れ値があるとどう違うか

data_out = np.append(np.random.RandomState(0).normal(50, 5, 100), 500.0)
z = (data_out - data_out.mean()) / data_out.std()
med = np.median(data_out); iqr = np.subtract(*np.percentile(data_out, [75, 25]))
r = (data_out - med) / iqr

外れ値1点が標準偏差を膨らませ、標準化では正常点が中央に潰れます。

距離ベース手法はなぜスケールに敏感か（図解）

生スケールでは A に近いのは C だが、標準化すると B の方が近い——答えが変わる。

手順①：fit と transform を分ける

sc = StandardScaler().fit(X_train)     # 訓練データから平均・標準偏差を学習
print("平均:", sc.mean_[:3].round(2), " 標準偏差:", sc.scale_[:3].round(2))
平均: [12.96  2.29  2.36]  標準偏差: [0.81 1.06 0.27]

この分離がデータリークを防ぐ鍵になります。

手順②：必ず訓練データだけで fit する

  1. 訓練・テストに分割する
  2. 訓練だけで fit
  3. 同じ統計量で両方を transform
sc = StandardScaler().fit(X_train)        # ← fit は訓練のみ
X_train_s = sc.transform(X_train)
X_test_s = sc.transform(X_test)           # ← テストは transform だけ
print("テストの平均は厳密には0でない:", X_test_s.mean(axis=0)[:3].round(3))
テストの平均は厳密には0でない: [0.182 0.154 0.037]

0ちょうどにならないのが、訓練の統計量を使った証拠。

Python デモ①：スケーリングで KNN は伸びるか

0.72 → 0.94。 スケールを揃えただけで13変数すべてが効くようになりました。

Python デモ②：3手法を横並びで比較

どの手法でも生データを大きく上回る。「揃えること」自体が効いている。

Python デモ③：カテゴリ変数の符号化

city = pd.DataFrame({'都市': ['東京', '大阪', '札幌', '東京', '大阪']})
enc = OneHotEncoder(sparse_output=False).fit(city[['都市']])
out = pd.DataFrame(enc.transform(city[['都市']]).astype(int), columns=enc.categories_[0])
print(pd.concat([city, out], axis=1).to_string(index=False))

東京   0   0   1

1,2,3と数値化すると偽の大小関係が生じる。独立した列に開く。

Python デモ④：スケーリングはクラスタリングにも効く

0.37 → 0.90。 クラスタリングでも前処理は必須です。

結果の解釈①：なぜ改善したか

生データの距離 ≒ proline だけで決まっていた：
proline              314.9
magnesium             14.3
alcalinity_of_ash      3.3
color_intensity        2.3
  • 生データでは距離が proline（標準偏差315）にほぼ独占されていた
  • 標準化で全変数が「標準偏差1」に揃い、13変数が対等に距離へ寄与
  • だから KNN・k-means の両方で大きく改善した

改善の本質は「無視されていた変数を復活させた」こと。

結果の解釈②：どの手法を選ぶか

手法 変換後の範囲 主な用途
標準化 平均0・分散1 回帰・分類・距離全般
MinMax [0,1] 画像・ニューラルネット
Robust 中央値0付近 外れ値の多いデータ

迷ったら標準化。

結果の解釈③：スケーリングが不要なケース

  • 決定木・ランダムフォレスト・勾配ブースティングは、各変数を独立に閾値分割するのでスケール不変
  • 一方、距離ベース（KNN・k-means）・正則化つき回帰（Ridge/Lasso）・PCAは敏感
スケール敏感   : KNN, k-means, SVM, Ridge/Lasso, PCA, ニューラルネット
スケール不変   : 決定木, ランダムフォレスト, 勾配ブースティング

「とりあえず標準化」は安全。ただし木系には効果なし。

正解率は上がった——ただ、この読みには落とし穴があるかもしれない。

落とし穴①：データリーク（最重要）

鉄則：fit は訓練データだけ。 テストには transform だけを当てる。

落とし穴②：リークは性能を「水増し」する

ラベルはでたらめなのに 0.75 と出ます。本番では出ません。評価が嘘になる。

落とし穴③：欠損補完・前処理の順序

  • 欠損補完：テストの値も使って平均を計算→補完すると、テスト情報が訓練に漏れる
  • 変数選択：前スライドのように、全データで選ぶと選択自体がリーク
  • 対数変換・外れ値除去：閾値を全データで決めると同じ罠

fit を伴うあらゆる前処理が、リークの入口になりうる。

発展①：Pipeline で前処理をまとめる

Pipeline は前処理とモデルを1つのオブジェクトに束ねる。

pipe = Pipeline([
    ('scaler', StandardScaler()),
    ('knn', KNeighborsClassifier(n_neighbors=5)),
])
pipe.fit(X_train, y_train)        # scaler.fit→transform→knn.fit を自動連結
acc = accuracy_score(y_test, pipe.predict(X_test))
print(f"Pipeline の正解率 = {acc:.3f}")
Pipeline の正解率 = 0.944

pipe.fit は訓練データだけで scaler を fit する。リークを構造的に防げるのが最大の利点。

発展②：前処理と交差検証の入れ子

交差検証では、前処理を各 fold の中でやり直さねばならない。

pipe = Pipeline([('sc', StandardScaler()),
                 ('knn', KNeighborsClassifier(n_neighbors=5))])
scores = cross_val_score(pipe, X_all, y_all, cv=5)   # fold ごとに scaler を fit
print(f"5分割CV 各スコア: {scores.round(3)}")
print(f"平均 = {scores.mean():.3f}")
5分割CV 各スコア: [0.944 0.944 0.972 1.    0.886]
平均 = 0.949

cross_val_score に Pipeline ごと渡すと、fold ごとに訓練部分だけで scaler が fit される。手で標準化してから CV するのは、全 fold にまたがるリーク。

できること・できないこと

前処理 できること 注意点
スケーリング 距離手法を機能させる 木系には効かない
One-Hot 符号化 カテゴリを数値化 列が増える
Pipeline リークを構造的に防ぐ 必ず使う習慣をつける

限界： 前処理は情報を増やさない。欠損の真値は復元できない。

まとめ

  1. スケールの違いは距離ベース手法を壊す 生データでは大スケール変数が距離を独占する（KNN 0.72→0.94、k-means ARI 0.37→0.90）

  2. スケーリングは訓練データだけで fit する テストの統計量を使うとデータリーク——評価が水増しされる

  3. Pipeline でリークを構造的に防ぐ 前処理とモデルを束ね、交差検証にも Pipeline ごと渡す
